# PNG (core) and HEIC (plugin) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PNG files show up in the grid as built-in items and HEIC/HEIF files via a new `heif` plugin, both with capture date (and GPS for HEIC) from one shared EXIF parser.

**Architecture:** The existing private TIFF/EXIF parser in `src/library/exif.cpp` becomes a public `parseExifBlock`. PNG is a built-in `MediaHandler` (header parse in pb_core, stb decode in pb_imaging) registered ahead of plugin formats. HEIC is a plugin using libheif that reaches the shared EXIF parser through a new `PbHost::parse_exif` callback (plugin ABI 5).

**Tech Stack:** C++20, doctest, vendored `third_party/stb/stb_image.h`, libheif ≥ 1.16 (plugin only), CMake/pkg-config.

**Spec:** `docs/image-formats-spec.md`

## Global Constraints

- pb_core must not depend on stb or libheif; the core never names the `heif` plugin.
- Plugins include only `src/plugin/photobrowse_plugin.h` and never link pb_core/pb_imaging.
- No file I/O or decoding on the render thread; all new code runs on workers.
- Never install system packages. The heif plugin needs `libheif-dev` and `libheif-plugin-libde265`, which aren't installed on this machine. Task 6 starts by checking `pkg-config --modversion libheif`. If that fails, stop and ask the user to install them.
- No colour management, HDR gain maps, Live Photo pairing, AVIF/WebP, or XMP parsing (spec §2 non-goals).
- HEIC: EXIF orientation is ignored (libheif applies `irot`/`imir`). PNG: EXIF orientation is applied with `applyOrientation`.
- A missing or unparsable EXIF block is never an error. The item gets `takenAt = 0`, so the file time is used.
- Plugin ABI: `PB_PLUGIN_ABI_VERSION` becomes **5**. The host still refuses other versions (existing policy), so all in-tree plugins are rebuilt. Smaller `struct_size` tables of version 5 still load.
- Tests use fixtures from `photos/` by file name via `pbtest::photo(name)`. They are not committed, and that matches existing practice.
- Fixture facts (verified 2026-10-23):
  - `IMG_3310.PNG`: 8-bit, 1170×2532, eXIf `DateTimeOriginal` "2026:06:16 21:56:20", orientation 1, no GPS.
  - `IMG_3590.PNG`: 16-bit Display P3, 1170×2532, "2026:06:20 10:54:09".
  - `SBWF6980.PNG`: 1024×1536, no metadata.
  - `IMG_2073.HEIC`: 4032×3024, orientation 1, "2025:11:27 19:32:57", GPS 34.2377917 N, 116.8723528 W, altitude 2112.55 m.
  - `IMG_5693.HEIC`: orientation 6, so 3024×4032 as displayed, no GPS, "2026:07:03 18:14:32".

## Review Focus

1. Portrait HEIC (`IMG_5693.HEIC`, orientation 6) must come out upright exactly once, both as reported size and as pixels. Test in Task 6.
2. A 16-bit Display P3 screenshot must decode to a normal-looking 8-bit image, not black or saturated. Test in Task 3 (mean luminance bounds).
3. Truncated or corrupt PNG/HEIC files must make the item broken without crashing. Tests in Task 3 (truncated PNG) and Task 6 (truncated HEIC copy).
4. Non-ASCII folder names (e.g. `Tromsø/`) must work for HEIC on every OS. Test in Task 6 (copy a fixture into a `ø` directory).
5. Several workers decoding HEICs at once must give correct results with no cross-talk from the per-thread file cache. Test in Task 6 (8 threads, two files).

  ```cpp

  std::optional<Image> decodePng(std::span<const uint8_t> data);

  class PngHandler final : public MediaHandler {  // stateless, thread-safe
   public:
    std::optional<MediaProbe> probe(const std::filesystem::path& abs) const override;
    std::optional<Image> decodeStill(const std::filesystem::path& abs, uint32_t minLongEdge) const override;

  ```

- Produces (C ABI, exact text from spec §4.4):
  ```c
  /* ---- Since version 5 ---- */
  /* Parses a TIFF/EXIF block (starting at "II*\0" or "MM\0*") and sets taken_at and the
   * GPS fields of *out (width/height untouched). 1 if the block was valid, else 0.
   * Thread-safe; callable from probe. */
  int (*parse_exif)(void* ctx, const uint8_t* tiff, size_t size, PbMediaInfo* out);
  ```
  It sets `taken_at` only when a date is present, sets `has_gps`/lat/lon (and `has_altitude`/altitude) only when GPS is present, and otherwise leaves `*out` alone. It returns 0 for a null pointer or a non-TIFF block.

  ```cpp
  // The TIFF block inside a HEIF "Exif" item: skips the 4-byte big-endian offset (ISO
  // 23008-12) and checks for "II*\0"/"MM\0*". Empty span if invalid.
  std::span<const uint8_t> exifTiffFromItem(std::span<const uint8_t> item);
  // Index of the smallest thumbnail whose long edge >= minLongEdge; -1 = decode the primary.
  int chooseThumbnail(std::span<const std::pair<uint32_t, uint32_t>> thumbSizes, uint32_t minLongEdge);
  // Whole file via std::ifstream on fs::path(u8 string), so UTF-8 paths work on Windows.
  std::optional<std::vector<uint8_t>> readFileUtf8(const char* pathUtf8);
  ```
- Plugin (`heif_plugin.cpp`):
  - Name `"heif"`, version `"1.0"`, extensions `{".heic", ".heif", NULL}`.
  - At entry, if `!heif_have_decoder_for_format(heif_compression_HEVC)`, log `PB_LOG_ERROR` "libheif has no HEVC decoder; install libheif-plugin-libde265 (Linux) or a libheif with libde265" and return a table with `extensions = NULL`.

  - **decode_still:** if `chooseThumbnail(…) >= 0`, decode that thumbnail, otherwise the primary. Use `heif_colorspace_RGB` with `heif_chroma_interleaved_RGBA` and default decoding options (transformations applied). Copy rows by stride into `out->alloc(w, h)`.
  - **Per-thread file cache (spec §4.3):** a `std::mutex`-guarded `std::unordered_map<std::thread::id, Cached>`, where `Cached` holds the path, size, mtime, file bytes and `heif_context*`. A call reuses its own thread's entry when path, size and mtime match, otherwise replaces it. `destroy` frees every entry. The context comes from `heif_context_read_from_memory_without_copy` over the cached bytes.
