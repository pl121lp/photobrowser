# Map View Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `M` shows a zoomable OpenStreetMap panel on the right with a dot for the open
photo (flying between locations) or dots for the visible grid photos. Tiles come from a
new `maptiles` plugin; the core stays network-free.

**Architecture:** Pure map logic in `src/map/` (pb_core: Mercator maths, map camera with
fly path and fit, tile bookkeeping, the map view state machine). `MapTiles` (pb_app)
runs tile fetches on a dedicated 2-thread pool against a `TileSource`, which the
`PluginHost` provides from any plugin that fills the new ABI v2 tile fields. GL drawing
reuses `TileRenderer` (tiles from one 4096² `PagedTexture` of 256-px slots) plus a small
`MapRenderer` for the dots. The `maptiles` plugin does HTTP(S) with libcurl, decodes
with stb_image and keeps a disk cache.

**Tech Stack:** C++20, SDL3, OpenGL 4.1 core, doctest; plugin: libcurl, stb_image
(vendored).

**Spec:** `docs/map-spec.md` (read it whole first), plus `docs/architecture.md` §13 and
`CLAUDE.md`.

## Global Constraints

- The core gains **no dependency**. All network code, libcurl and stb_image live only in
  `plugins/maptiles/`. The core never names a plugin; it uses the first loaded plugin
  that offers a tile source (a second one logs a warning).
- `pb_core` (incl. `src/map/`) stays free of SDL and OpenGL. GL only in `src/gfx`, SDL
  only in `src/app/app.cpp`. POSIX/Win32 calls only in `src/platform/`.
- OpenGL 4.1 core / GLSL 410 only.
- No network, file I/O or image decoding on the main thread. Tile fetches run on their
  **own pool of 2 threads**, never on the photo decode workers.
- Web Mercator, 256-px tiles, XYZ (`z/x/y`, y from the north), latitude clamped to
  ±85.0511287798°, x wraps modulo 2^z.
- Map zoom range 2 to the source's maximum (OSM 19). `[map] photo_zoom` default 15;
  grid auto-fit max zoom 16, padding 10% per side; single dot → photo zoom; on open
  with a photo the map starts at zoom 4 and flies in.
- Slide in/out 350 ms ease-in-out cubic; refit after 300 ms of grid rest; halo pulse
  2 s after the map arrives; fly path van Wijk & Nuij, ρ = 1.42, duration clamped to
  0.6–3 s; tile cross-fade 150 ms.
- Messages (exact text): `Map needs a map tile plugin (start with --plugin; see README)`,
  `Map unavailable: no internet connection`, `Map tile server refused requests`,
  `No location for this photo`, `No locations among the visible photos`. Notices show
  for 4 s near the top centre of the window.
- ABI: `PB_PLUGIN_ABI_VERSION` 1 → 2, fields only appended; host, video plugin and the
  fake test plugin change in one commit.
- OSM policy: `User-Agent: PhotoBrowse/<version> (+https://github.com/pl121lp/photobrowser)`,
  attribution always visible, disk cache honouring `Cache-Control: max-age` (7 days when
  absent), no prefetch beyond the view and its ancestors, at most 2 connections, 60 s
  back-off after 403/429.
- New settings get a documented entry in `defaultConfigText()` and a test.
- Write the failing test first for all pure logic. Run the whole suite before each
  commit: `cmake --build --preset linux-debug && ctest --test-dir build/linux-debug --output-on-failure`.
- Commit after every task, conventional message, ending with
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Photos either side of the antimeridian** (lon 179.9 and −179.9) → the map flies the
   short way (east/west across 180°) and tiles left/right of the seam draw from wrapped
   keys. Tests: Task 1 `mercator: tiles covering a view across the antimeridian wrap`,
   Task 3 `fly: takes the short way across the antimeridian`.
2. **Bad or extreme GPS values** (lat 89.9, lat −90, NaN from a corrupt EXIF) → clamped
   to the Mercator limit, NaN positions skipped; no NaN reaches the camera. Tests: Task 1
   `mercator: latitude clamps, non-finite positions are rejected`, Task 6
   `map view: non-finite photo positions are ignored`.
3. **Window resize or fullscreen toggle while the map is open or sliding** → panel and
   content keep their proportions, the map keeps its centre, the grid keeps its centre
   photo. Tests: Task 5 `map view: resize keeps proportions and map centre`, Task 5
   `interaction: narrowing viewport keeps the centre photo centred and the open photo fitted`.
4. **A tile source returning a wrong-size or empty image** (a provider serving 512-px
   tiles, a corrupt PNG) → treated as `Error` (drawn from the ancestor), never uploaded.
   Test: Task 8 `plugins: tile source results are validated`.
5. **Closing the map or quitting while fetches are in flight** on a slow network → no
   uploads after close, queued requests cancelled, destruction waits only for the
   running fetches. Test: Task 9 `map tiles: cancelAll and destruction with fetches in flight`.

  constexpr double kTilePx = 256;

  Vec2d toWorld(double lat, double lon);              // lat clamped to ±kMaxMercatorLat

  struct TileKey {
    int z = 0, x = 0, y = 0;                          // x, y already wrapped / in range

    friend bool operator==(TileKey, TileKey) = default;

  std::vector<TileCover> tilesCovering(const Rect& world, int z);
  // Level whose texels are closest to device pixels, magnified at most ~1.4x:

**Files:**

**Interfaces:**
- Produces:
  ```cpp
  // src/map/fly_path.h. Views as (centre, w) with w = visible width in world units.
  class FlyPath {
   public:
    FlyPath(Vec2d c0, double w0, Vec2d c1, double w1, double rho = 1.42);
    double length() const;                     // S
    void at(double s, Vec2d& c, double& w) const;  // s in [0, S]; exact ends at 0 and S
  };
  // MapCamera additions
  static constexpr double kFlyMinS = 0.6, kFlyMaxS = 3.0;
  void flyTo(Vec2d worldCenter, double zoom, double t);  // from the current state, even mid-flight
  bool flying() const;
  struct MapViewState { Vec2d center; double zoom; };
  // Box of `points` (world) with `padding` (fraction of the viewport per side), zoom capped at
  // maxZoom; a single point (or all equal) gives singleZoom; empty -> nullopt.
  static std::optional<MapViewState> fitView(std::span<const Vec2d> points, Vec2d viewport, double uiScale,
                                             double padding, double maxZoom, double singleZoom, double minZoom);
  ```
- Fly algorithm (d3-interpolate-zoom), with `d = |c1 − c0|`, ρ = 1.42:
  - `d < 1e-12`: `S = |ln(w1/w0)| / ρ`; `w(s) = w0·exp(sign(w1−w0)·ρ·s)`; `c = c0`.
  - else `b0 = (w1² − w0² + ρ⁴d²) / (2·w0·ρ²·d)`, `b1 = (w1² − w0² − ρ⁴d²) / (2·w1·ρ²·d)`,
    `r0 = ln(√(b0²+1) − b0)`, `r1 = ln(√(b1²+1) − b1)`, `S = (r1 − r0)/ρ`;
    `u(s) = w0/ρ² · (cosh r0 · tanh(ρs + r0) − sinh r0)`, `w(s) = w0 · cosh r0 / cosh(ρs + r0)`,
    `c(s) = c0 + (c1 − c0)·u(s)/d`.
  - `flyTo`: `w = viewport.x / worldPx-at-zoom` (i.e. `viewport.x / (256·2^zoom·uiScale)`);
    before building the path shift the target x by ±1 so `|dx| ≤ 0.5`; duration
    `clamp(S · 1.0 s, 0.6, 3.0)`; progress `s = S · easeInOutCubic(elapsed/duration)`;
    a drag, wheel or `jumpTo` stops the flight. Zero-length path (same view) = no flight.
- [ ] **Step 1: Write the failing tests:**
  - `fly: starts and ends exactly at the given views` — for c0 {0.1,0.2}, w0 0.01 → c1
    {0.6,0.3}, w1 0.001: `at(0)` and `at(S)` reproduce the inputs to 1e-12.
  - `fly: zooms out mid-way for long distances, not for short ones` — long (d 0.5,
    w 0.001 both ends): `w(S/2) > 10·w0`; short (d = 0.2·w0): `w(s) ≤ w0·1.05` for all s.
  - `fly: pure zoom and zero length` — same centre: `S == |ln(w1/w0)|/ρ`; identical views: `S == 0`.
  - `map camera: flyTo lands on the target and the duration is clamped` — a long fly
    ends (`!flying()`) after ≤ 3.0 s and ≥ 0.6 s at the exact centre/zoom; a tiny one ends
    no earlier than 0.6 s.
  - `fly: takes the short way across the antimeridian` — from lon 179.9 to lon −179.9 at
    zoom 10: during the flight `toLatLon(center).lon` never lies in [−170, 170].
  - `map camera: a new flyTo mid-flight starts from the current state` — no jump in centre
    between the frame before and after the second `flyTo` (delta < one frame's movement).
  - `map camera: fitView contains every point with padding and respects maxZoom` — for 3
    points spread over a city: every point's screen position lies inside the viewport

  ```cpp
  // src/map/tile_source.h
  enum class TileStatus { Ok, Missing, Offline, Refused, Error };
  struct TileResult { TileStatus status = TileStatus::Error; Image image; };  // image 256x256 when Ok
  class TileSource {
   public:
    virtual ~TileSource() = default;
    virtual TileResult get(int z, int x, int y) const = 0;  // worker threads, may block
    virtual std::string attribution() const = 0;
    virtual int minZoom() const = 0;
    virtual int maxZoom() const = 0;
  };

  // src/map/tile_set.h
  struct MapTileDraw {
    Rect screen;          // panel-relative px of the wanted tile
    UvRect uv, uvPrev;    // in the single 4096² map page (slot UV composed with the sub-rect)
    float fade = 1;       // weight of uv over uvPrev
  };
  struct TileRequest { TileKey key; int64_t priority; std::shared_ptr<CancelToken> cancel; };
  class TileSet {
   public:
    static constexpr double kFadeS = 0.15, kOfflineRetryS = 5, kRefusedRetryS = 60;
    TileSet(int minZ, int maxZ);       // one page of 256 slots (16x16 of 256 px)
    void frame(const MapCamera& cam, double now, std::vector<MapTileDraw>& draws,
               std::vector<TileRequest>& requests);
    std::optional<SlotRef> loaded(TileKey k, double now);  // nullopt = drop (no free slot)
    void failed(TileKey k, TileStatus s, double now);
    void cancelAll();                    // every requested tile back to "not requested"
    size_t pending() const;              // requested, not yet loaded/failed
    bool fading(double now) const;
    Vec2d slotOrigin(SlotRef s) const;   // texel origin of the slot in the page
  };
  ```
- Rules: level `L = tileLevel(cam.zoom, cam.uiScale, minZ, maxZ)`; wanted = `tilesCovering(cam.visibleWorld(), L)`
  plus backstop ancestors at level 2 and at `L−3` (when > 2) covering the view.
  Request priority (lower first): level-2 backstop `0`, `L−3` backstop `1<<32`, visible
  `2<<32` + squared px distance from the panel centre (rounded). A wanted, not-resident
  tile draws its nearest resident ancestor's matching sub-rect; tiles with no resident
  ancestor are not drawn. A newly loaded tile cross-fades from that ancestor over 150 ms.
  Requested tiles not wanted this frame are cancelled (token set, state reset). Missing
  and Error are never retried this session; Offline retried after 5 s, Refused after
  60 s. `loaded` takes a free slot or evicts the least recently used tile not used this
  frame (ties: deeper level first).
- [ ] **Step 1: Write the failing tests** (camera 800×600, uiScale 1):
  - `tile set: wanted tiles for a view, coarse levels first` — at zoom 10 over Oslo: the
    requests include every key of `tilesCovering(visibleWorld, 10)`, plus level-2 and
    level-7 ancestors; sorted by priority, the first is level 2, all level-7 before any level-10.
  - `tile set: ancestor fallback picks the nearest loaded ancestor and its sub-rect` — load
    only (8, x>>2, y>>2) for a wanted (10,x,y): its draw's `uv` equals the slot UV composed
    with the sub-rect `{(x%4)/4, (y%4)/4, (x%4+1)/4, (y%4+1)/4}`; then load (9, x>>1, y>>1)
    → that one is used.
  - `tile set: loaded tiles cross-fade from the ancestor` — fade 0 right after load, 1 after 0.15 s.
  - `tile set: missing is not retried, offline is retried after 5 s` — `failed(Missing)` →
    never requested again; `failed(Offline)` → re-requested on a frame ≥ 5 s later, not before.
  - `tile set: unwanted requests are cancelled` — request at zoom 10, then move the camera
